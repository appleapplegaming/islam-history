# Domain docs

Single-context repo.

## Before exploring, read these

- `GLOSSARY.md` at the repo root (key terms: witness, scene, ref, certainty, ayat journal, ...)
- `docs/adr/`: ADRs touching the area you work in
- `docs/design.md`: the game design

If `GLOSSARY.md` or `docs/adr/` do not exist yet, proceed silently; `/domain-modeling` creates them
when a term or decision is actually settled.

## Use the glossary's vocabulary

Name domain concepts as `GLOSSARY.md` defines them, in tickets, test names and code. If you
contradict an ADR, say so explicitly instead of silently overriding it.
